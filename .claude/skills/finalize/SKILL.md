# /finalize — シーンを確定し、記録を更新する

対象: $ARGUMENTS（空なら status が draft の原稿があるシーンを示して作者に選んでもらう）

## 原則

- 記録の元にするのは、作者が直し終えた原稿だけ。原稿に書かれていないことを状態に書かない
- **作者の承認を得るまで、どのファイルにも書き込まない**
- canon/ には書かない。正典に無い新事実は `/canonize` の候補として示すだけにする

## 手順

1. 読む: 対象シーン（`story/scenes/NNN-*.md`）、`output/*/` の同名の原稿、`story/state.md`、`story/threads.md`、シーンの `related` にある canon/ のファイル
   - 原稿が無ければ、先に `/draft` するよう伝えて終わる
   - 原稿が複数の媒体にあれば（`-alt` の別案も含む）、どれを基準にするか作者に聞く。媒体間で出来事が食い違っていたら、その点も伝える
   - 対象シーンが既に fixed なら再確定として扱う。前回の確定内容（シーンの `summary`・「後で変わったこと」、state.md、threads.md）との差分だけを変更案にし、同じ内容を二重に積まない
2. 変更案を作り、まとめて作者に示す
   - **シーン**: frontmatter の `summary`（1 行、40 字程度）と `## このシーンの後で変わったこと`（箇条書き）。基準の原稿とシーンの `## 出来事`・`## 伏線`・`## 重要な小道具` が食い違っていれば、骨格の修正案も示す（原稿が正）
   - **state.md**: 登場したキャラごとに、居場所・知っていること・持ち物・体の状態・関係の変化の差分。「最後に更新したシーン」をこのシーンにする。初登場のキャラは見出しを追加。ただし「最後に更新したシーン」が対象より後のシーンになっているキャラは上書きしない。代わりに、後のシーンへの影響として作者に知らせ、該当シーンの `/check` を提案する
   - **threads.md**: まず、シーンの `## 伏線` と台帳の既存行（`/develop` で登録済みのもの）を原稿と照合する
     - 原稿で実際に張られている既存行は、そのまま使う。新しい ID を振り直さない
     - 予定していたのに原稿で張られていない既存行は、回収予定の変更か dropped を提案する
     - 台帳に無い伏線・問いだけを追加する（ID は台帳の最大 ID + 1、状態 open、張ったシーンにこのシーン）。回収予定はシーン番号で書き、決まっていなければ「未定」とする。追加した ID はシーンの `## 伏線` にも書き足す
     - 回収したものは「回収したシーン」を埋めて closed に
     - 既存行の回収予定が言葉（「後半」など）で書かれていたら、シーン番号か「未定」に直す案を示す（回収予定はシーン番号で書く規則）
   - **正典の候補**: 原稿で初めて出た固有名詞・過去の出来事・設定。`/canonize` で入れるかどうかを作者に聞く
3. 作者の承認を待つ。修正の指示があれば反映して再提示する
4. 承認された分を書き込む。基準の原稿とシーンの status を `fixed` にし、書き換えた全ファイルの `updated` を今日にする。state.md と threads.md を書き換えたら、それぞれの frontmatter の related にこのシーンを足す
5. 回収予定を過ぎても open の伏線があれば知らせる
6. コミットを提案する。メッセージ例: `確定: 010-arrival`
