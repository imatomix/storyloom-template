# 確認 3：コマンドの連携の通し確認

`/interview` の追加（PR #4）のあと、テンプレートを複製した空の作品で、コマンドを順に実際に動かして、コマンド同士の受け渡しを確かめた。作者役は `docs/qa/author-persona.md`（AI）。

## 方法

- 題材：『四十五リットル』。亡くなった祖母の家を、30 代の兄妹（千秋・直哉）が売却の引き渡しまでの三日間で片付ける短編小説（1〜2 万字）
- 順番：`/kickoff` → `/develop 妹` → `/interview 千秋 一日目` → `/status` → `/canonize` → `/develop シーン` → `/draft novel 010` → `/finalize 010` → `/check` → `/interview 直哉 010` → `/interview 千秋 010`
- すべて `claude -p` と `--continue` で動かし、作者役として受け答えした
- 作った作品は、ファイルを直した後の規則に合わせて、記入例 `examples/yonjugo-rittoru/` に入れた
- `-p` では、canon/ への書き込みはフックで止まる（確認済み）。作者が承認する回だけ、QA 用の複製でフックを一時的に外した

## うまく動いたこと

- `/develop` の次の一手に `/interview` が出る → インタビューの候補が `ideas.md` に残る → `/status` が「未解決の問い」に拾う → `/canonize` で正典に入れる、までがつながった
- `/interview` の境界：
  - 下書きだけのキャラ：正典でないと伝えてから始めた
  - シーン番号でない時点（「一日目」）：時点を聞き直した
  - ファイルの無いキャラ：始めずに `/develop` を提案した
  - 同じ日の 2 回目：記録のファイル名に `-2` を付けた
- `/interview` の答えが時点を守った。見ていない日めくりの月は答えず、見ていない兄の袋の数は「音でわかった」と答えた
- `/finalize` の後の `/interview` は、`story/state.md` の状態で答えた
- `/kickoff`・`/canonize`・`/finalize` は、全文や差分を見せて承認を得てから書き込んだ
- `/draft` は、シーン設計の承認後に本文を書き、分量が目安より 3 割短いことを自分から報告した
- `/check` は、本文とシーン設計の細かなずれ（「中身は書かない」と決めた冷蔵庫の中身が「瓶」とわかる、など）と、`/finalize` による状態記録の書き漏れを拾った

## 見つかったテンプレートの課題と対応

| 課題 | 対応 |
|---|---|
| `related` の基準が「相対パス」としか書かれておらず、コマンドごとにルートから・ファイルから・story/ からの 3 通りで書かれた。`/check` は記入例と逆の書き方に揃えるよう提案した | CLAUDE.md に「リポジトリのルートからのパス」と明記。構造検査で、すべての `related` を確認する |
| `/kickoff` が、作者が却下していないログライン案を、推測の理由付きでボツ（`rejected.md`）にした。記入例は別案として `ideas.md` に残している | 選ばれなかった案は `ideas.md` に別案として残し、作者が却下した案だけを `rejected.md` に記録する |
| `/develop` が「`/interview 千秋 一日目`」と、シーン番号でない時点を案内した | 案内に「時点はシーン番号。シーンが無ければ省略」と添える |
| 正典に入れた候補が `ideas.md` に残り続け、`/status` が再び挙げるおそれがある | `/canonize` が項目の末尾に `（→ 正典 YYYY-MM-DD）` を付け、`/status` は処理済みとして除く |

## テンプレートの課題ではなかったこと

- QA 用の作業フォルダが信頼済みでないため、`-p` で git と計測スクリプトが動かなかった（確認 2 と同じ）
- `/finalize` が状態記録の細部を書き漏らした（`/check` が拾った）
- `/develop` が、正典になっている設定を「まだ正典ではない」と読み違えた（指摘すると直した）
