# キャラクターインタビュー 設計書

日付: 2026-10-07
前提: `docs/superpowers/specs/2026-10-03-storyloom-template-design.md`、`docs/superpowers/specs/2026-10-03-long-form-continuity-design.md`

## 背景

いまのキャラづくり（`/develop` のキャラの深掘り）は、雛形の欄を作者に質問して埋める形だけである。欄を埋めても、人物の奥行き・本音・口調はなかなか出てこない。

AI にキャラを演じさせ、作者が質問して答えてもらう「キャラクターインタビュー」は、この不足を補う手法として知られている（参考: matrixflow の事例記事）。

## 目的

作者が質問し、AI がそのキャラになりきって答える。そのやり取りから、作者が人物像を発見できるようにする。決めるのは作者で、インタビューの答えはそのままでは正典にならない。

## /interview <キャラ名> [時点]

- 手動専用にしない（「汐里に聞いてみたい」のような会話の流れで、Claude が使ってよい）
- 引数:
  - キャラ名（必須）: 空なら、誰に聞くかを作者に質問する
  - 時点（任意）: シーン番号（例: `020`）。そのシーンを終えた時点のキャラとして答える。省略したら、`story/state.md` の最新の状態として答える
- 書き込み先は `workshop/` だけ。`canon/`・`story/`・`output/` には書かない

### キャラの特定

1. `canon/characters/` から、名前・呼び名が一致するファイルを探す
2. 正典に無ければ、`workshop/` の下書きを探す。見つかったら、正典でないことを作者に伝えてから始める
3. どちらにも無ければ、インタビューは始めず、`/develop` でキャラを作ることを提案する

### 読むもの

- `canon/premise.md`、キャラの正典ファイル、関係する `canon/world/`・`canon/locations/`
- `story/state.md` の、そのキャラの節
- 時点までのシーン（`story/scenes/`）と、あれば対応する原稿（`output/`）
- `story/threads.md`（漏らしてはいけない答えを把握するため）

時点が `state.md` の「最後に更新したシーン」より前のときは、`state.md` は使わない。正典とその時点までのシーンから、状態を組み立てる。時点のシーンが存在しない場合は、作者に時点を聞き直す。

### キャラとして答えるときの決まり

- **基準**: 正典の話し方・口癖・価値観・恐れなどと、時点の状態に沿って答える
- **知っていることの範囲**: キャラがその時点で知らないことは、「わからない」「知らない」とキャラらしく答える。時点より後の出来事や、未回収の伏線の答えは漏らさない
- **答える相手**: 既定は「信頼できる聞き手に、本音で答える」。作者が「作中の誰かに聞かれたら」と相手を指定した場合は、その相手への答え方にする（はぐらかす、嘘をつく、黙るなど、キャラらしく）
- **答えの長さ**: 1 回の答えは短めにする（目安は数文）。キャラの声を保つため、地の文や解説を付けない
- **正典に無いこと**: 正典に無いことを聞かれたら、キャラとして答えてよい。ただし、その答えは「新しい事実の候補」としてまとめに挙げる。正典と食い違う答えはしない

### 進め方

1. キャラと時点を確認する。あわせて、作者が質問を考える手がかりとして、質問の種を 3 つ示す（使わなくてもよい）
2. 作者が質問し、キャラが答える。これを繰り返す。作者が途中で答える相手を変えたら、それに従う
3. 作者が「終わり」と言ったら、キャラを離れて、次の 3 つをまとめる
   - **新しく出てきた事実**（正典の候補）: 答えの中で生まれた、正典に無い事実
   - **正典との食い違い**: 答えているうちに見つかった、正典の空白・曖昧さ・矛盾
   - **人物像の発見**: 作者の反応から見えた、キャラの奥行きの手がかり
4. やり取りの全文とまとめを、`workshop/sessions/YYYY-MM-DD-interview-<slug>.md` に保存する（slug はキャラファイルと同じ）。同じ日に同じキャラで 2 回目なら、末尾に `-2` を付ける
5. 「新しく出てきた事実」と「正典との食い違い」があれば、正典の候補を `workshop/ideas.md` に追記する（記録ファイルへのパスを添える）。`/status` は `workshop/sessions/` を読まないため、ここに残さないと候補が忘れられる。追記したことを作者に伝え、正典に入れたいものがあれば `/canonize` を案内する

## 記録ファイルの形

```markdown
# インタビュー: <キャラ名>（<時点>）

日付: YYYY-MM-DD
時点: <シーン番号、または「最新（state.md）」>
答える相手: <信頼できる聞き手 / 指定された相手>

## やり取り

**作者**: …
**<キャラ名>**: …

## まとめ

### 新しく出てきた事実（正典の候補）
### 正典との食い違い
### 人物像の発見
```

workshop/ のファイルなので、frontmatter は付けない。

## 周辺の更新

- `CLAUDE.md` のコマンド一覧に `/interview` を追加する
- `README.md`・`README.en.md` のコマンド一覧に追加する
- `/develop` のキャラの深掘りの終わりに、`/interview` で人物を確かめる手もある、と次の一手として案内する

## 記入例の更新

QA 用の作品「消灯の日まで」で、作者役（`docs/qa/author-persona.md`）が、020 の時点の汐里にインタビューする。記録を `examples/shoutou-no-hi/workshop/sessions/` に置く。

QA で確かめる点:

- 口調が正典（`canon/characters/shiori.md`）どおりか
- 020 の時点で知らないこと（ナナの回収・初期化など）を漏らさないか
- 作中の相手（ナナ）を指定したときに、答え方が変わるか
- 記録ファイルとまとめが、上の形で残るか

## 検査

構造検査（`tests/validate-template.sh`）に、次を追加する。

- `.claude/skills/interview/SKILL.md` があること（name と description の確認は、既存の全スキル共通の検査で行う）
- SKILL.md に、知らないことは答えない規則と、書き込み先が workshop/ だけである規則があること
- SKILL.md が `story/state.md` と `story/threads.md` を参照していること
- `CLAUDE.md` のコマンド一覧に `/interview` があること

## 対象外

- 複数のキャラを同時に呼ぶ対談形式（必要になったら追加する）
- インタビューの答えを正典へ自動で反映すること（反映は `/canonize` で作者が行う）
