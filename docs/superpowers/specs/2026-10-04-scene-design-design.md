# シーン設計と書式ガイドの充実 設計書

日付: 2026-10-04
前提: `docs/superpowers/specs/2026-10-03-storyloom-template-design.md` ほか既存の設計書

## 背景

記入例の出力が、小説・映像・漫画のいずれも単調で情報量が少なかった。原因は 2 つ。

- 使い方: 作者役が「おまかせ」ばかりで、`/draft` に渡る材料（見せ場・情景・心情）が無かった
- テンプレート: `/draft` が骨格（出来事の箇条書き）からいきなり本文を書く。書式ガイドに、カバレッジや描写の技法、漫画のコマに必要な情報の項目が無い

## 目的

書く前に「何を見せ、何を感じさせるか」を作者と合意し、媒体ごとに十分な情報量で書けるようにする。

## 決定事項（確認 1）

- シーンの中を **場面**（ひとまとまりの見せ場の単位。脚本なら柱が立つ程度のまとまり）に分けて設計する
- 映像の成果物は **脚本まで**。ショット表（カット割り）は作らない
- 漫画の成果物は **漫画（文字コンテ）** と明記する。到達点は、作画する人がそのまま下描きに入れる程度の情報量
- 媒体ごとの分量は **目安**。作者がいつでも直せる
- 形式の見本: `docs/qa/scene-design-sample-010.md`

## 1. シーン設計

### 置き場所と形式

シーンファイル（`story/scenes/NNN-*.md`）に `## シーン設計` 節を追加する。骨格（`## 出来事` など既存の節）は「何が起きるか」、シーン設計は「どう見せるか」を担う。

```markdown
## シーン設計

### 全体
- **このシーンの核**：
- **見せ場**：
- **心情の山**：
- **忘れられない具体**：
- **緩急**：

### 場面

#### 場面 1　（名前）（静／動／会話 などの調子）
- **見せるもの**：
- **感覚の細部**：光・音・匂い・温度・手触り など
- **心情**：外（見えるもの）／内（起きていること）
- **台詞で言わせないこと**：

### 媒体ごとの分量と狙い

| 媒体 | 分量の目安 | 狙い |
|---|---|---|
| 小説 | 字数 | |
| 映像（脚本） | 分 | |
| 漫画（文字コンテ） | ページ数 | |
```

場面ごとの項目は、該当しないものは省略してよい。媒体ごとの表は、想定媒体（`canon/premise.md`）にある媒体だけを書く。

### 作る流れ

- `/draft` の最初に、対象シーンの `## シーン設計` が空なら設計を作る。作者に見せて承認を得てから、シーンファイルに書き込み、本文に進む
- 設計は媒体に依存しないので、2 つ目以降の媒体の `/draft` では既存の設計を使う（分量と狙いの行だけ足す）
- 設計を作るときは、作者に「見せ場」と「心情の山」を必ず尋ねる。「おまかせ」と言われたら 2〜3 案を示して選んでもらう
- `/develop` でシーンを作るときに、作者が望めば設計まで作ってよい

### 分量の目安の扱い

- 目安は守るべき上限ではない。`/draft` は目安を参考に書き、2 割以上外れたら理由を作者に報告する
- 作者は目安をいつでも直せる。直したら `/draft` で書き直すか `/revise` で調整する

## 2. 書式ガイドの充実

### 共通: 書き終えた後の確認

各ガイドの末尾に「書き終えた後の確認」を置き、`/draft` は書き終えたら次を確かめて作者に報告する。

- シーン設計のすべての場面が原稿にあるか
- 各場面の「感覚の細部」が使われているか
- 「台詞で言わせないこと」を台詞で言っていないか
- 分量が目安から 2 割以上外れていないか
- 媒体ごとの確認項目（下記）

### 映像（`references/film.md`）— 脚本のみ

- ショット表の節を削除する
- 柱・ト書き・台詞の書式に加え、次を定める
  - ト書きは「見えるもの・聞こえるもの」を現在形で書く。カメラの指示（寄り・パンなど）は書かない
  - 音（環境音・効果音）と光の変化をト書きに書き、場面の空気を作る
  - 間は「間」と一行で書く。長い沈黙は、何が見え何が聞こえているかで書く
  - 人物の動きと表情で心情を示す。心情そのものはト書きに書かない
  - 尺の目安: 200 字詰め原稿用紙 1 枚でおよそ 1 分
- 確認項目: 場面の変わり目に柱が立っているか、台詞なしの場面がト書きだけで成立しているか

### 漫画（`references/manga.md`）— 文字コンテ

- 名称を「漫画（文字コンテ）」に改める（「ネーム」の語を使わない）
- ページごとに: ページの狙い（このページで読者に何を感じさせるか）、めくり
- コマごとに次の項目を書く

  | 項目 | 内容 |
  |---|---|
  | 大きさ・位置 | 大／中／小、ページ内の位置（上段右など）、形（横長・縦長・ぶち抜き） |
  | 構図 | 距離（引き・バスト・アップ）とアングル（俯瞰・煽り・目線） |
  | 人物 | 表情・ポーズ・演技・視線の向き |
  | 背景 | 場所・時間・天候、描き込みの程度（描き込む／省略／白） |
  | 台詞 | 話者、吹き出しの種類と位置 |
  | モノローグ・ナレーション | 枠の種類 |
  | 効果音・効果 | 描き文字、集中線・トーンなど |
  | 間 | 無言のコマの意図 |

- 確認項目: 各ページに狙いがあるか、無言のコマに意図が書かれているか、作画する人が迷う空欄が無いか

### 小説（`references/novel.md`）

- 「描写の技法」の節を追加する
  - 五感を使う（視覚に偏らない）
  - 心情を行動・身体感覚・小道具に置き換える
  - 情景と心情を重ねる（心情に呼応する光・音・天候）
  - 時間の伸縮（心情の山では時間を引き延ばし、移行の場面は短く）
  - 内面の語りの量を、作品の決めごと（心の声の扱い）に合わせる
- 既存の「書き終えた後の確認」に、共通の確認項目を加える

## 3. 用語の統一

テンプレート全体（CLAUDE.md、README、README.en、`/draft` の説明、`output/README.md`、書式ガイド）で次を統一する。

- 「脚本＋ショット表」→「脚本」
- 「ネーム」→「漫画（文字コンテ）」または「文字コンテ」

既存の記入例（`examples/`）のショット表と「ネーム」の表記は、記入例を作り直すときに直す（この設計の範囲外）。

## 4. 使い方のコツ（README）

README に「使い方のコツ」の節を追加する。

- 「おまかせ」を減らし、選択肢から選ぶか、一言でも具体的に答える
- 文体の見本は自分で書く
- シーン設計の「見せ場」「心情の山」「忘れられない具体」は、作者が自分で決める
- 分量の目安を決めてから書かせる

## 検証（確認 2）

- 構造検査に追加: シーン雛形の `## シーン設計`、film.md にショット表が無いこと、テンプレート側のファイルに「ネーム」が残っていないこと、各ガイドの「書き終えた後の確認」、README の「使い方のコツ」
- QA: `docs/qa/author-persona.md` の作者役で、シーン 010 を設計から作り直し、小説・映像（脚本）・漫画（文字コンテ）の 3 媒体で書く。作者（人間）が読んで判断する
  - 足りていれば、記入例の作り直しと README の更新に進む（別作業）
  - 足りなければ、書式ガイドを調整するか、`/revise` の映像・漫画への拡張を検討する

## 対象外

- `/revise` の映像・漫画への拡張（確認 2 の結果で判断）
- 記入例の作り直し（確認 2 の後）
