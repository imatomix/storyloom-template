# シーン設計と書式ガイドの充実 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 書く前に場面ごとの「見せ方」を作者と合意するシーン設計を導入し、映像（脚本）・漫画（文字コンテ）・小説の書式ガイドを、十分な情報量で書けるよう充実させる。

**Architecture:** シーンファイルに `## シーン設計` 節を足し、`/draft` が最初に設計を作って承認を得る。書式ガイドは媒体ごとの書き方と「書き終えた後の確認」を持ち、`/draft` は書き終えたら確認結果を報告する。

**Tech Stack:** Markdown、Claude Code skills、bash 3.2 互換の検査スクリプト

**Spec:** `docs/superpowers/specs/2026-10-04-scene-design-design.md`

## Global Constraints

- 文書・コミットメッセージは日本語。コミット末尾に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
- 用語: シーンの中の単位は「場面」。映像の成果物は「脚本」、漫画の成果物は「漫画（文字コンテ）」。テンプレート側に「ネーム」「ショット表」を残さない（`docs/`・`examples/` は除く）
- 分量は目安。2 割以上外れたら理由を報告する

## Review Focus

1. **`/draft` が設計の承認前に本文を書く** — 手順で「承認後に本文」を明記（Task 2）
2. **2 つ目の媒体で設計を作り直してしまう** — 既存の設計を使い、分量の行だけ足す（Task 2）
3. **「おまかせ」で設計の見せ場・心情の山が AI 任せになる** — 2〜3 案から選ばせる（Task 2）
4. **用語の取り残し** — 検査で「ネーム」「ショット表」を検出（Task 4）
5. **想定媒体に無い媒体の行を設計に書く** — premise の想定媒体だけ書く（Task 1 の雛形コメント・Task 2）

````markdown
引数: $ARGUMENTS（1 つ目が媒体、2 つ目がシーン。足りなければ作者に聞く）

## 手順

1. 媒体の書式ガイドを読む: `references/film.md`（脚本）、`references/novel.md`（小説）、`references/manga.md`（漫画の文字コンテ）のうち該当するもの
2. 読む:
   - 対象シーンのファイル、その `related` にある canon/ のファイル、`canon/premise.md`（トーンと想定媒体）

   ---
   status: draft
   related:
     - story/scenes/<シーンファイル名>
   updated: YYYY-MM-DD
````

````markdown
# 映像（脚本）の書式

日本の脚本書式で、脚本だけを書く。カット割り（ショット表・絵コンテ）は監督・絵コンテ担当の仕事として残し、書かない。

## 書式

```
○ 場所（時間帯）

　ト書き。現在形で、見えるもの・聞こえるものだけを書く。

人物名「台詞」
人物名（N）「ナレーション」
人物名（M）「モノローグ（心の声）」
人物名（OFF）「画面外の声」

　間

　ト書き。
```

## 書き方

- **柱（○）**: シーン設計の場面が変わり、場所か時間が変わるたびに立てる。回想・時間経過は `（回想）` `（数日後）` などを柱に添える
- **ト書き**
  - 見えるもの・聞こえるものを現在形で書く。カメラの指示（寄り・引き・パンなど）は書かない
  - 光の変化と音（環境音・効果音）を書き、場面の空気を作る。シーン設計の「感覚の細部」をここに置く
  - 心情そのものは書かず、動き・表情・手元・視線で示す
  - 一段落は短く。動きが変わるたびに段落を分ける
- **間**: 台詞のない時間は「間」と一行で書く。長い沈黙は、その間に何が見え、何が聞こえているかで書く
- **台詞**: 口に出す言葉だけ。説明台詞を避け、シーン設計の「台詞で言わせないこと」を台詞にしない
- **尺の目安**: 200 字詰め原稿用紙 1 枚でおよそ 1 分

## 書き終えた後の確認

- シーン設計のすべての場面が脚本にあるか。場面の変わり目に柱が立っているか
- 各場面の「感覚の細部」がト書きに書かれているか
- 台詞の無い場面が、ト書きだけで成立しているか
- 「台詞で言わせないこと」を台詞で言っていないか。ト書きに心情を書いていないか
- 尺が目安から 2 割以上外れていないか（外れたら理由を報告する）
````

````markdown
# 漫画（文字コンテ）の書式

漫画の文字コンテ（コマ割り・構図・人物・台詞などを文字で書いた設計図）を書く。到達点は、作画する人がそのまま下描きに入れる程度の情報量。日本の漫画の読み順（右から左、上から下）を前提にする。

## 書式

```
想定ページ数: 14

## P1（左ページ）
- ページの狙い: 夜の岬の静けさと、汐里の孤独を一枚で見せる
- めくり: 最後のコマで、塔の扉に手をかける

### コマ1（大・上段から中段のぶち抜き・横長）
- 構図: 引き。俯瞰で岬全体
- 人物: 汐里、画面の下端に小さく。リュックの肩紐を握っている。視線は塔
- 背景: 夜の岬。細い月。塔から伸びる光の帯が草地を横切る。描き込む
- 台詞: なし
- ナレーション: なし
- 効果音・効果: ザ…ン（遠い波）。光の帯は白抜き
- 間: 物語の始まりの静けさ。読者に一呼吸置かせる
```

## コマの項目

| 項目 | 書くこと |
|---|---|
| 大きさ・位置 | 大／中／小、ページ内の位置（上段右など）、形（横長・縦長・ぶち抜き・枠なし） |
| 構図 | 距離（引き・バスト・アップ・寄り）とアングル（俯瞰・煽り・目線） |
| 人物 | 誰が、どんな表情・ポーズ・演技で、どこを見ているか |
| 背景 | 場所・時間・天候と、描き込みの程度（描き込む／省略／白・ベタ） |
| 台詞 | 話者、吹き出しの種類（通常／叫び（トゲ）／心の声（もこもこ）／電話・機械（ギザ）／小・ゆれ線）と位置 |
| モノローグ・ナレーション | 枠の種類（角枠・枠なし） |
| 効果音・効果 | 描き文字、集中線・トーン・ベタフラッシュなど |
| 間 | 無言のコマの意図。読者に何を感じさせたいか |

該当しない項目は「なし」と書く（空欄にしない）。

## ページのルール

- 右綴じでは奇数ページが左、偶数ページが右に来る。偶数ページとその次の奇数ページは見開きで同時に目に入るため、ページをめくるのは奇数ページ（左）の後だけ
- 「めくりの引き」は奇数ページ（左）の最後のコマに置く。めくった直後の偶数ページ（右）の最初のコマに、引きを受ける絵を置く
- 開始ページが奇数（左）である前提。偶数始まりになる場合は作者に確認する
- 1 ページ 4〜7 コマを目安。シーン設計の見せ場は大ゴマ・ぶち抜き・見開きで
- フキダシ 1 つに 30 字程度まで。長い台詞は分ける
- 冒頭に想定ページ数を書く

## 書き終えた後の確認

- シーン設計のすべての場面がコマにあるか。見せ場に大ゴマ以上を使っているか
- 各ページに「ページの狙い」があるか。奇数ページの最後にめくりの引きがあるか
- 各コマの項目に空欄が無いか（作画する人が迷う箇所が無いか）
- 無言のコマに「間」の意図が書かれているか
- 「台詞で言わせないこと」を台詞・モノローグにしていないか
- ページ数が目安から 2 割以上外れていないか（外れたら理由を報告する）
````
