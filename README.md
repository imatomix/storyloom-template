# storyloom-template

[English](README.en.md)

AI（[Claude Code](https://docs.claude.com/en/docs/claude-code/overview)）と一緒に、映像・小説・漫画の物語を作るためのテンプレートです。
作者が主導し、Claude は質問・提案・矛盾チェック・下書きを担当します。コードは無く、Markdown のファイルと Claude Code のスキル・フックだけでできています。

## 特徴

- **決めるのは作者**：Claude は案を 2〜3 個出し、質問で掘り下げます。確定した設定（正典）は、作者が承認したときしか書き換えません。フックがそれを機械的に守ります
- **1 つの骨格から 3 つの媒体へ**：媒体に依存しないシーンの骨格から、脚本（＋ショット表）・小説・漫画のネームに書き起こせます
- **長い作品でも崩れない**：キャラの現在の状態、伏線台帳、シーンごとの 1 行あらすじを、作者が原稿を確定するたびに更新します。`/check` が設定の矛盾や回収されていない伏線を見つけます
- **読める記入例つき**：制作途中の短編「消灯の日まで」の小説版を `examples/` に収録しています。この作品は、テンプレートの動作確認（QA）の工程で AI（Claude）が作成したもので、作者役の受け答えも含めて人間は書いていません

## 使っている様子

実際のやり取りの抜粋です（記入例「消灯の日まで」を作ったときのもの。一部省略。この作品は当初漫画と映画で作り、のちに媒体を小説と映画に切り替えています）。

```
> /kickoff

質問 1 / 7：何を作りたいですか？
ぼんやりした種で十分です。
- 場面：「雨の駅のホームで、二度と会えないはずの人とすれ違う」
- 問い：「記憶を全部失っても、同じ人を好きになるのか？」 …

> 廃止が決まった離島の灯台で、古い灯台守ロボットと、
  家出してきた14歳の少女が出会う話を作りたいです。

> /brainstorm 灯台守ロボットの設定

案 1：契約が切れるまで動いている
案 2：忘れられているから動いている
  ⚠️ 正典との関係：ログラインの「消灯の日まで律儀に灯を守り続ける」と合わない可能性があります
案 3：古い設計のせいで止まれない …

> 案 3 が一番好きです。案 2 はボツにします。

workshop/rejected.md に案 2 を理由付きで追加しました。

> /finalize 010

原稿が漫画と映画の 2 つの媒体にあります。スマホの場面が食い違っています。
- 映画：電源ボタンに親指を置くが、押さない
- 漫画：電源を入れてしまい、「お母さん　未読 12件」が見える
漫画を基準にする場合、正典 canon/characters/shiori.md の「恐れ」と食い違います。
確定の作業では canon/ には書き込みません。/canonize の候補としてお示しします。
質問：どちらを基準にして確定しますか？
```

## はじめ方

1. GitHub の **Use this template** から自分のリポジトリを作るか、複製する
   ```bash
   git clone https://github.com/imatomix/storyloom-template.git my-story && cd my-story
   rm -rf .git docs/superpowers && git init   # テンプレート自体の履歴と開発資料は不要なら削除
   ```
2. Claude Code を起動して `/kickoff` を実行する
3. 記入例は `examples/` を参照（不要になったら削除してかまいません）
   - `kaze-no-tegami/` — 短い作品。各ファイルの埋め方の見本
   - `shoutou-no-hi/` — 制作途中の作品。状態記録・伏線台帳・確定の運用の見本

必要なもの: Claude Code、jq（canon/ 保護フックが使用。macOS 15 以降は標準で入っています。jq が無い環境では、すべての書き込みで確認が出ます）

## 考え方

ファイルを「どれだけ確定しているか」で 4 つに分けています。

| フォルダ | 意味 | Claude が書くか |
|---|---|---|
| `canon/` | 正典。確定した設定 | `/canonize` で作者が承認したときだけ |
| `story/` | 物語の骨格（媒体に依存しない） | 依頼されたとき、`/develop`・`/finalize` で |
| `workshop/` | 作業場。アイデア・検討・ボツ案・取材資料 | 自由に |
| `output/` | 媒体別の成果物 | `/draft` で。`/finalize` は status だけを変える |
| `examples/` | 記入例 | 書かない（参照のみ） |

同じ `story/` から、映像・小説・漫画のどれにも書き起こせます。

## コマンド

| コマンド | 用途 |
|---|---|
| `/kickoff` | 作品の前提（ジャンル・テーマ・ログライン等）を決める |
| `/brainstorm [テーマ]` | 壁打ち。質問と案出しで広げる |
| `/develop <対象>` | キャラ・世界観・場所・シーン・構成を 1 つ深掘りして下書きする |
| `/canonize <ファイルや案>` | 下書きを正典に昇格させる（差分を見て承認） |
| `/check [範囲]` | story/・output/ と正典の矛盾、回収されていない伏線を一覧にする |
| `/draft <film\|novel\|manga> <シーン>` | シーンを脚本・小説・ネームに書き起こす |
| `/finalize <シーン>` | 直し終えた原稿を確定し、1 行あらすじ・キャラの状態・伏線台帳を更新する |
| `/status` | 進捗を集計して STATUS.md を更新し、次の一手を提案する |

`/kickoff`・`/canonize`・`/finalize` は作者が呼んだときだけ動きます（Claude が自分の判断では呼びません）。

## 典型的な流れ

```
/kickoff → /brainstorm → /develop → /canonize → （story/ を組み立てる）→ /draft → （作者が直す）→ /finalize → /check → /status
```

順番は固定ではありません。行き来しながら進めてください。

## 長い作品の一貫性

- `story/state.md` — キャラの現在の状態（居場所・知っていること・持ち物など）
- `story/threads.md` — 伏線台帳。張った伏線と未回収の問い
- シーンの `summary` — 1 行あらすじ。`/draft` は全シーンを読まずに、これで流れをつかむ

いずれも作者が原稿を直し終えた後の `/finalize` で更新します。`/check` は回収予定を過ぎた伏線や、シーン順に見た状態の矛盾も検出します。

## canon/ の保護

Claude が `canon/` に Edit/Write するたびに、フック（`.claude/hooks/guard-canon.sh`）が確認を求めます。自動承認のモードでも確認は省略されません。
既知の制限: Bash コマンド経由の書き込みはフックの対象外です（CLAUDE.md のルールで抑止しています）。

## 個人設定

自分だけの設定は `.claude/settings.local.json` に書いてください（git 管理外）。

## モデルの指定

矛盾チェック（`.claude/agents/continuity-checker.md`）は読むファイルが多いため、`model: sonnet` を指定しています。細かな矛盾の見落としが気になる場合は `model: inherit`（会話と同じモデル）に変えてください。

## 動作確認

テンプレートを変更したら、構造の検査を実行します。

```bash
bash tests/validate-template.sh
```

コマンドの動きは、新しいディレクトリにテンプレートを複製して次の順に試します。

1. `/kickoff` → `/brainstorm` → `/develop` → `/canonize` → `/draft novel` → （原稿を手直し）→ `/finalize` → `/check` → `/status`
2. 確認すること
   - `/canonize` で canon/ に書き込むときに確認が出る
   - `/finalize` が承認の前に書き込まず、状態記録と伏線台帳を更新する
   - story/ に正典と矛盾する記述をわざと入れると、`/check` が検出する
   - `/status` で STATUS.md が更新される

## 記入例について

`examples/` の 2 作品は、どちらも AI（Claude）が作成したもので、人間の作者はいません。

- `kaze-no-tegami/` — テンプレートを作るときに、各ファイルの見本として Claude が書いた
- `shoutou-no-hi/` — 動作確認（QA）の工程で作った。Claude が作者役として質問に答え、別の Claude Code のセッションがその答えを受けてコマンドを実行した

## リポジトリの構成

| パス | 内容 |
|---|---|
| `CLAUDE.md` | Claude の振る舞いのルール |
| `.claude/skills/` | 各コマンド（スキル） |
| `.claude/agents/` | 矛盾チェック用のサブエージェント |
| `.claude/hooks/` | canon/ 保護フック |
| `canon/`・`story/`・`workshop/`・`output/` | 作品のファイル（雛形） |
| `examples/` | 記入例 |
| `tests/` | テンプレートの構造検査とフックのテスト |
| `docs/superpowers/` | このテンプレート自体の設計書と実装計画（開発の記録）。作品づくりには不要なので、利用時は削除してかまいません |
